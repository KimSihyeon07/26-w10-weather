# 실시간 날씨·미세먼지 대시보드 (`26-w10-weather`)

> Open-Meteo 공개 API와 React 19, Lucide React를 활용하여 구축한 반응형 실시간 기상 및 대기환경 모니터링 대시보드입니다.

---

## ⛅ 소개

이 프로젝트는 전 세계 실시간 기상 데이터와 대기질(미세먼지) 관측 정보를 직관적이고 미려한 카드 UI로 제공하는 종합 기상 대시보드 웹 애플리케이션입니다.

- **주요 도시 원클릭 조회**: 서울(강서/시청), 인천, 부산, 대구, 대전, 광주, 제주 등 주요 도시 즉시 조회
- **실시간 날씨 정보**: 현재 기온, 체감 온도, 습도, 풍속 및 WMO 기상 코드에 대응하는 날씨 아이콘과 한국어 상태 표시
- **환경부 기준 미세먼지 진단**: PM10, PM2.5 수치와 환경부 4단계 등급('좋음', '보통', '나쁨', '매우 나쁨') 컬러 뱃지 및 프로그레스 바 시각화
- **24시간 기온 추이 차트**: 경량 SVG 꺾은선(Polyline) 차트로 오늘 하루 시간대별 기온 변화와 날씨 아이콘을 가로 스크롤로 제공
- **7일간 주간 예보**: 향후 일주일간의 최고/최저 기온 막대 게이지 및 강수 확률(%) 표시
- **실시간 도시 검색**: 전 세계 도시를 라틴/한글로 검색하고 자동완성 드롭다운을 통해 기상 정보 조회

## 📡 데이터는 어떻게 가져오나요 (외부 API 아키텍처)

- **Open-Meteo 날씨 및 미세먼지 API의 특징**:
  - 회원가입이나 Secret API Key 발급 없이도 무료로 호출 가능한 오픈 데이터 API입니다.
  - HTTPS 보안 프로토콜을 기본 지원하며, 위도(`latitude`)와 경도(`longitude`) 좌표를 기반으로 실시간 예보(`forecast`), 대기질(`air-quality`), 지오코딩(`geocoding`) 데이터를 고성능 JSON 형태로 응답합니다.
- **UI 컴포넌트(`App.jsx`)와 API 통신 로직(`src/api/weather.js`) 분리 이유 (Decoupling)**:
  - **관심사의 분리(Separation of Concerns)** 원칙을 적용하여 화면 렌더링을 담당하는 컴포넌트와 비동기 네트워크 통신 모듈을 완전히 격리했습니다.
  - 이를 통해 API 엔드포인트 변경, 응답 데이터 스키마 수정, 또는 테스트를 위한 Mock 데이터 교체 시 UI 컴포넌트의 수정 없이 `weather.js`만 단독으로 유지보수할 수 있습니다.
- **도시 검색 시 디바운스(Debounce) 적용 이유**:
  - 검색창에서 사용자가 키보드를 누를 때마다(예: `S` -> `e` -> `o` -> `u` -> `l`) 즉각 API를 호출하면 찰나의 순간에 수십 번의 불필요한 HTTP 요청이 발생합니다.
  - 이는 클라이언트 측 네트워크 낭비뿐만 아니라 API 서버에 DoS(서비스 거부) 공격과 유사한 부하를 유발하며, 서버로부터 `429 Too Many Requests`(Rate Limit)로 IP가 차단될 수 있습니다.
  - 이를 방지하기 위해 사용자의 타이핑이 멈춘 후 **400ms 지연** 타이머를 거쳐 단 한 번만 최종 검색어를 호출하도록 디바운싱을 적용했습니다.

## 🛡️ 보안에서 확인한 것 (사이버보안과 체크포인트)

- **공개 API(Public API) vs 비밀 키 API(Private/Secret API)의 보안 차이**:
  - Open-Meteo와 같은 완전 공개 API는 브라우저(React 클라이언트)에서 직접 호출해도 보안상 무방합니다.
  - 하지만 결제, 금융, 사내 데이터베이스 연동과 같이 **비밀 키(Secret Key)**가 필요한 유료/보안 API는 절대로 프론트엔드 코드에 하드코딩하거나 직접 통신해서는 안 됩니다.
- **프론트엔드 직접 호출의 위험성과 백엔드 프록시(BFF, Backend For Frontend)의 필수성**:
  - 프론트엔드에 Secret Key를 포함하면 브라우저 개발자 도구의 `Network` 탭이나 빌드된 자바스크립트 번들 파일(`dist/*.js`)에서 100% 평문으로 노출됩니다.
  - 악의적인 공격자가 이 키를 탈취하여 무제한 API를 호출하면 막대한 과금 피해가 발생하거나 중요 데이터가 탈취될 수 있습니다.
  - 따라서 비밀 키를 안전한 백엔드 환경 변수(`.env`)에 격리하고, 클라이언트는 자사 백엔드 프록시 서버를 통해서만 검증된 요청을 중계받는 **BFF 아키텍처**를 반드시 구축해야 합니다.
- **HTTPS 환경에서의 Mixed Content(혼합 콘텐츠) 차단 원리**:
  - HTTPS로 암호화 배포된 웹사이트에서 안전하지 않은 `http://` API 엔드포인트를 호출할 경우, 브라우저는 보안 정책에 의해 해당 통신을 강제 차단(`Blocked Mixed Content`)합니다.
  - 이는 평문 HTTP 통신 구간에서 제3자가 데이터를 도청하거나 가로채 악성 코드를 주입하는 중간자 공격(MITM, Man-in-the-Middle)을 방어하기 위한 브라우저의 핵심 보안 메커니즘입니다.

## 🎨 커스터마이징한 부분

기본 요구사항 외에 사용자 편의성과 시각적 완성도를 높이기 위해 다음 2가지 추가 기능을 구현했습니다:

1. **최근 본 도시 저장 및 원클릭 재방문 (옵션 B)**:
   - `localStorage`(`recent_weather_cities`)와 연동하여 사용자가 검색하거나 선택한 도시를 최대 5개까지 최근 순으로 자동 보관합니다.
   - 상단 빠른 선택 바 아래에 **"최근 본 도시"** 뱃지 칩 목록을 배치하여 클릭 한 번으로 이전 조회 도시의 날씨를 즉시 다시 확인할 수 있으며, 필요 시 기록을 전체 삭제할 수 있는 [지우기] 기능을 제공합니다.
2. **섭씨(°C) ↔ 화씨(°F) 실시간 단위 변환 토글 스위치 (옵션 D)**:
   - 상단 헤더 우측에 `°C / °F` 세그먼트 토글 버튼을 탑재하여 버튼 클릭 한 번으로 모든 온도를 상호 변환(`F = (C * 9/5) + 32`)합니다.
   - 현재 기온, 체감온도뿐만 아니라 24시간 시간별 기온 차트와 7일 주간 예보의 일자별 최고/최저 기온 막대 게이지까지 일관되게 환산 반영됩니다.
   - 선택된 온도 단위는 `localStorage`(`weather_temp_unit`)에 보관되어 새로고침 후에도 유지됩니다.
